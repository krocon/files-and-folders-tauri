# Design 057: Dialog-Knöpfe per Tastatur

Status: umgesetzt (02.11.2026, selbständig ohne Haltepunkt – Anweisung von Marc: Empfehlungen des Prompts selbst
entscheiden) · Branch `feat/dialog-tasten` · reines Frontend (Phasen 1/3/5 zusammengelegt, kein Rust)

## Entscheidungen

|        | Entscheidung                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Begründung                                                                                                                               |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **E1** | Direktive **`appDialogKey`** (`shared/dialog/dialog-key.ts`) mit den Rollen `primary`, `cancel`, `secondary:<L>`, `destructive:<L>`, `null` (keine Rolle, z. B. in einem anderen Zustand). Die Direktive meldet sich per DI beim umgebenden `Modal` an (`register`/`unregister`); der `Modal` wertet **alle** Tasten in seinem einen `keydown`-Handler aus. Keine `keydown`-Handler je Dialog.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Eine Mechanik für 40 Dialoge; Rollen stehen am Knopf, wo man sie beim Lesen des Templates sieht.                                         |
| **E2** | **Enter** klickt den ersten sichtbaren `primary`-Knopf (DOM-Reihenfolge), egal ob der Fokus in Textfeld, Checkbox, Radio oder Select steht. **Nicht**: Fokus auf einem Knopf/Link/`summary`/`[role=button]` (der fokussierte gilt – nativ), `textarea`, `contenteditable`; innerhalb von `combobox`/`listbox`/`option`/`menu`/`menuitem`/`tree`/`grid`/`tablist`/`[aria-expanded=true]`/GuiExpert-Table/`app-preview-grid`/`[data-own-enter]`; `isComposing` (IME); mit Modifier (Mod+Enter bleibt den bisherigen Dialog-Kürzeln); `evt.defaultPrevented` (ein inneres Feld hat Enter schon behandelt, z. B. Vorlagenname, Pfadsuche); Ziel in einem **anderen** Formular als dem des Hauptknopfs (Schnellverbindung, Umbenennen-Feld). `evt.repeat` und ein `disabled` Hauptknopf: Enter wird geschluckt, nichts ausgelöst. Der Modal ruft `preventDefault()` – damit gibt es kein zusätzliches implizites Submit: **genau ein** Klick → genau ein `(submit)`. **Schutzregel:** ein destruktiver, nicht wiederherstellbarer Hauptknopf (heute `cancelFirst`) bekommt die Rolle `destructive:<L>` statt `primary` – Enter löst ihn nie aus, auch kein implizites Submit seines Formulars. **Esc** schließt wie bisher über `closed`, außer ein inneres Popup hat Esc schon genommen (`defaultPrevented`) oder der Fokus steht in einem `[role=menu]`. | Prompt-Empfehlung; `defaultPrevented` macht die vorhandenen Feld-Handler (`keydown.enter` + `preventDefault`) ohne Änderung verträglich. |
| **E3** | **`Mod+<Buchstabe>`** (⌘ macOS, Ctrl sonst) für Nebenknöpfe, **`Mod+Shift+<Buchstabe>`** für destruktive (`Delete permanently` = `Mod+Shift+D`). Buchstabe **fest im Template** (sprachunabhängig, berechenbar): erster Buchstabe des englischen Labels, der nicht reserviert und im Dialog frei ist. **Reserviert** (nie eine Rolle, `parseDialogKey` lehnt ab): `A C V X Y Z` (Textbearbeitung inkl. Redo `Ctrl+Y`) und `Q W H M` (macOS-System). Ausnahme: der Bestätigungsdialog (`confirm-dialog.ts`) leitet den Buchstaben aus seinem wechselnden Label ab (`letterFor`). Ausnahme 2: der **Konfliktdialog** behält seine Alt-Buchstaben (Design 005 E6, je Sprache unterstrichen) – er bekommt nur `primary` (Überspringen bzw. Umbenennen-Feld). Bestehende `Mod+Enter`-Kürzel (Kopieren, Packen, Gruppieren …) bleiben.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Eine Regel auf allen OS, kollidiert nicht mit Tippen; Shift als zweite Hürde, weil es keine zweite Rückfrage gibt.                       |
| **E4** | Jeder Knopf mit Rolle bekommt **`aria-keyshortcuts`** (`Enter`, `Escape`, `Meta+Shift+D` / `Control+Shift+D`; vorhandene Werte wie `Control+Enter Meta+Enter` bleiben angehängt) und einen **Tooltip** „Shortcut: ⇧⌘D“ / „Tastenkürzel: Ctrl+Shift+D“ (Darstellung über `formatStroke`, nie hart codiert; ein vorhandener `title` bleibt vorn: „Gone (Shortcut: …)“). **Während ⌘/Ctrl gehalten wird**, zeigen Knöpfe mit Buchstaben ein kleines Badge oben rechts (`D` bzw. `⇧D`, absolut positioniert → nichts verschiebt sich; CSS in `styles/controls.css`, Farben `--color-shortcut-*`). Kein dauerhaftes Badge, kein „↵“ im Hauptknopf (Dialoge bleiben ruhig; der Tooltip nennt Enter).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Prompt-Empfehlung.                                                                                                                       |

Plattform: `DIALOG_PLATFORM` (InjectionToken, Default `detectPlatform()`), damit Tests macOS/Windows schalten; der
Modal braucht so kein `ActionService`.

Bekanntes Risiko (nur im echten Fenster prüfbar): Das native macOS-Menü ist bei offenem Dialog deaktiviert
(`set_menu_enabled`); ob AppKit ein **deaktiviertes** Menü-Kürzel (z. B. ⌘D = Favorit) trotzdem schluckt, ist im E2E zu
prüfen. Fällt es auf, hilft ein anderer Buchstabe im Template.

## Tests

- `shared/dialog/modal.spec.ts`: Enter aus Text/Checkbox/Radio/Select → primary genau einmal (ein Submit); nicht aus
  textarea/Listbox/IME/Shift; repeat und disabled schlucken; fokussierter Nebenknopf nativ; innerer Handler gewinnt;
  destruktiver Hauptknopf nur per Mod+Shift (kein implizites Submit); Mod/⌘-Unterschied; Mod+A/C/V/X/Z bleiben im
  Feld; Esc + inneres Popup; Tooltip/ARIA (macOS, Windows, Deutsch); Badge beim Halten.
- `shared/dialog/dialog-roles.spec.ts`: jeder `.btn.primary` in einem Template mit `<app-modal` trägt `appDialogKey`;
  keine reservierten Buchstaben; Buchstaben je Dialog eindeutig.
- `ops/dialogs.spec.ts`: Marcs Fall (Enter = Papierkorb, Ctrl+Shift+D = endgültig, `cancelFirst` → Enter nichts),
  Mehrzahl `trashHint` (rot zuerst, Commit `fix(057)`).
- E2E im echten Fenster: in dieser Sitzung nicht möglich (siehe Bericht).
